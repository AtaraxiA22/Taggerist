## BULK RENAME — RECURSIVE '^'-STRIP CLI (user-run, not in repo)

- User asked for a CLI command to strip '^' from existing filenames,
  restricted to image + video extensions (.jpg/.jpeg/.png/.gif/.mp4/.mov/
  .avi/.mkv/.webm/.wmv/.m4v/.mpg/.mpeg/.3gp), run from the collection
  root. Final working command:

  find . -depth \( -iname '*.jpg' -o -iname '*.jpeg' -o -iname '*.png' \
    -o -iname '*.gif' -o -iname '*.mp4' -o -iname '*.mov' -o -iname '*.avi' \
    -o -iname '*.mkv' -o -iname '*.webm' -o -iname '*.wmv' -o -iname '*.m4v' \
    -o -iname '*.mpg' -o -iname '*.mpeg' -o -iname '*.3gp' \) -name '*^*' \
    -execdir bash -c 'for f in *^*; do [ -f "$f" ] && mv -f -- "$f" "${f//^/}"; done' \;

- Gotchas hit along the way (for future reference):
  - '*' quoting: inside SINGLE quotes a backslash is literal — '*\^*'
    matched nothing; correct pattern is bare '*^*'.
  - mv -i asks per-file (unwanted for hundreds of files); mv -f is silent,
    mv -n skips collisions without clobbering.
  - Find/mv are silent on success; a long 0%-CPU run is usually disk I/O
    (D state), not a hang. Diagnosis chain: ps --ppid walks find -> bash
    -> mv; mount responsiveness checked via ls.
  - User has files on both Data-A and Data-B; the find must be run from
    EACH collection root (find . is per-tree).
