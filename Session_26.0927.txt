4. **Taglist display overhaul — long design conversation (the big one)**
   User wants: short display names, section headers, all lists on one screen.
   Key decisions and facts established:
   - **Short names**: display only the root (after first underscore) in taglist
     and filenames. Sort key (full tag w/ prefix) stays hidden — prefixes keep
     doing their grouping job invisibly. Saves ~4 chars/tag (measured avg 3.97);
     a 10-tag tagline sheds ~40 chars.
   - **CSV format stays identical**: col1 = full tag (hidden grouping key),
     col2 = display name (new role), col3+ = aliases/conversion targets.
     When col2 absent, strip-rule derives display name (zzAGE_20-30 → "20-30").
     When col2 present, it wins. Header rows: col2 = section title text.
   - **Collision analysis (measured on the real CSVs)**: 368 distinct roots;
     27 roots under 2+ prefixes, nearly all benign PHT_/PHTO_ and FRN_/FURN_
     spelling dupes; only genuine semantic overlaps: housekeeping (ACT_/MOD_),
     locked (MOD_/PTY_). 6 roots are also aliases elsewhere (mailbox→ACT_mail).
   - **Headers**: ___ rows (CHR_-___CHARACTER___ etc.) render as bold
     non-clickable section titles; title text from col2 (e.g. "CHARACTERS",
     "AGES"). They are tags too — move with their prefix if user re-parks
     a category.
   - **Prefix = layout lever (user's insight)**: renaming AGE_ → zzAGE_ parks
     the category at bottom of sort = far right columns = hidden in the
     horizontally-scrolled margin. No code needed; also sorts to bottom of the
     CSV for editing convenience. Grid fills column-by-column (down then right),
     so list order = screen position.
   - **Delimiter stays underscore**: '$' unused in data (would work) but buys
     nothing; '!' already taken ([RW] uses leading-! rows like !CHR_JCC).
     Underscore: all 433 tags use it, roots never contain it.
   - **One screen**: 3 lists ≈ 420 tags + headers fit in ~600 capacity
     (8pt font, 16 columns, big monitor). Search already spans all 3 lists
     (verified in code) — consolidation is purely a display change.
   - **Taglist buttons retire** → replaced by font-size and column-count
     spin-controls. Live repaint (no [Refresh] needed); values write-through
     to config file for persistence across restarts (same mechanism as #0.23).
   - **Horizontal scrolling** on the grid: scroll area exists (setup_taglist_
     window, line 916) but currently squeezes; needs policy change + natural
     grid width.
